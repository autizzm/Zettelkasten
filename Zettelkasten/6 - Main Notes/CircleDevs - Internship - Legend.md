**Проект 1 — внутренняя SaaS-платформа для продуктивности** (Spring Boot, PostgreSQL, Redis, RabbitMQ, ~50 клиентов, 10K пользователей).  
  
# Сервис аналитики и дашбордов:  
Дашборд аналитики грузился 8–12 секунд. Я проанализировал медленные запросы через `EXPLAIN ANALYZE`, нашёл N+1 в JPA и отсутствие индексов, предложил решение тимлиду — переписать на native SQL, + добавил индексы и кэширование. После согласования реализовал: двухуровневый кэш (Caffeine + Redis) для собранных дашбюордов и pre-aggregation через Spring Batch.  
**Результат:** загрузка дашборда снизилась до 1.2–1.5 сек, нагрузка на БД — на 60%.  
# Сервис уведомлений  
Участвовал в переводе уведомлений с синхронной отправки на асинхронную через Kafka — Я занимался реализацией:  
- основная логика розолвинга провайдеров  
- догика сборки уведомлений из шаблонов при помощи Apache Velocity  
- inbox для идемпотентности,  
- интеграцию Resilience4j (retry, circuit breaker). Результат: latency API упала со 150мс до 30мс, потери уведомлений — с 2% до 0.01%.
