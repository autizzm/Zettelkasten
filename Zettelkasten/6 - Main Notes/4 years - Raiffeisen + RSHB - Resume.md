Описание проекта

Сервисная платформа банка, автоматизирующая пост-продажное обслуживание розничных клиентов: формирование и выдачу клиентских документов (справки, выписки, квитанции) и сопровождение проблемной задолженности (реструктуризация, работа с исполнительными производствами и арестами счетов, миграция legacy-функционала кредитного сопровождения на целевую платформу).

Что я делал

- Проектировал и разрабатывал доменную модель и бизнес-логику сервиса `debt-case-service` (Java 17, Spring Boot 3, Spring Data JPA, PostgreSQL), включая расчёт статусов просрочки, применяемых мер и агрегацию истории по кредитному делу.

- Реализовывал и сопровождал BPMN-процессы в **Camunda**: моделирование service tasks, boundary timer events для автоматической эскалации, обработка компенсирующих сценариев (rollback шагов процесса при отмене реструктуризации клиентом).

- Проектировал и реализовал ETL/reconciliation-слой (`legacy-collection-migration-service`) для поэтапной миграции кредитных дел: батчевая выгрузка снапшотов из legacy-системы и целевой БД, сравнение по ключевым полям, классификация расхождений (маппинг vs реальные данные), поэтапное переключение трафика по классам дел (strangler fig pattern). - ~={orange}**demo**=~

- Внедрил паттерны отказоустойчивости через **Resilience4j** (circuit breaker, bulkhead, half-open recovery) для защиты синхронных вызовов к нестабильному внешнему источнику данных об арестах/взысканиях от каскадной деградации; спроектировал трёхзначную семантику ответа («да / нет / неизвестно») вместо бинарной, чтобы корректно отличать отсутствие данных от сбоя интеграции.

- Реализовал идемпотентную обработку входящих сообщений и повторных вызовов (составной ключ дедупликации `clientId + requestType + timeWindow`, уникальный индекс в PostgreSQL) для защиты от дублирования уведомлений и записей аудита при ретраях на уровне BPMN-процесса и очереди сообщений.

- Оптимизировал производительность `document-generation-engine`: профилировал узкие места рендеринга PDF, перевёл обработку с однопоточной на пул воркеров с батчингом, вынес генерацию неперсонализированных частей шаблона в предгенерируемый кэш, добавил backpressure на приём сообщений из очереди при превышении порога загрузки.

- Писал unit-, компонентные (с поднятием Spring-контекста) и интеграционные тесты (**JUnit 5, Mockito, Testcontainers, WireMock**) в рамках тестовой пирамиды, принятой в команде; поддерживал покрытие критичных доменных сценариев в ~={orange}**Allure TestOps**=~.

- Участвовал в дежурствах, расследовании и устранении продовых инцидентов, включая экстренные откаты через `hotfix`-ветки и последующие корректирующие патчи.

- Проводил код-ревью PR коллег.

Достижения:

1. **Оптимизация производительности сервиса генерации документов.** Устранил узкое место в однопоточной обработке рендеринга PDF в `document-generation-engine`: снизил p95 времени рендера документа с 3.1 секунды до 380 миллисекунд за счёт перехода на пул воркеров с батчингом и предгенерируемого кэша шаблонов; пропускная способность сервиса выросла с 800 до 3500 документов в сутки на том же количестве вычислительных ресурсов.

2. **Автоматизация reconciliation при миграции legacy-системы.** Спроектировал и внедрил автоматический механизм сверки данных между legacy- и целевой системой сопровождения кредитов, сокративший объём еженедельной ручной проверки аналитиком с 400 до 15–20 кредитных дел; это стало ключевым фактором, позволившим команде перенести свыше 40 000 кредитных дел на целевую платформу без потери качества данных.

3. **Отказоустойчивая интеграция с нестабильным внешним источником данных.** Внедрил Resilience4j (circuit breaker + bulkhead + half-open recovery) для интеграции с внешним источником данных об арестах и взысканиях счетов, устранив каскадную деградацию зависимых сервисов при сбоях upstream; время реакции на недоступность источника сократилось с полного ожидания таймаута (15–20 секунд) до практически мгновенного возврата явного статуса «неизвестно».

4. **Формализация процесса эскалации в BPMN.** Перевёл полностью ручной процесс эскалации при непринятом предложении о реструктуризации в автоматизированный BPMN-процесс с таймерными событиями и интеграцией с очередью задач оператора, обеспечив предсказуемые и аудируемые сроки обработки каждого случая 

5. **Повышение устойчивости обработки сообщений через идемпотентность.** Спроектировал схему дедупликации входящих сообщений и повторных вызовов BPMN-процесса на основе составного ключа с уникальным индексом в PostgreSQL, устранив риск дублирования клиентских уведомлений и записей аудита при автоматических ретраях на уровне очереди и оркестратора процессов.


## Обо мне - хуйня какая-то

Backend-разработчик с фокусом на построении надёжных распределённых систем в domain-driven-подходе — в частности, в доменах с высокими требованиями к точности данных и аудируемости (финансовые расчёты, юридически значимые процессы). Основной стек — Java/Spring экосистема, работа с оркестрацией бизнес-процессов (Camunda/BPMN), асинхронной обработкой сообщений и паттернами отказоустойчивости (Resilience4j, circuit breaker, bulkhead).

Умею разбираться в производительности систем на уровне профилирования узких мест, а не только на уровне добавления ресурсов — предпочитаю находить и устранять причину деградации, будь то однопоточная обработка, отсутствие идемпотентности или неверная семантика обработки ошибок внешних интеграций. Имею опыт проектирования миграций legacy-систем по паттерну strangler fig с гарантией целостности данных через автоматическую сверку, а не ручной контроль.



### РСХБ

**Цифровой канал дистанционного банковского обслуживания юридических лиц**  
Микросервисная платформа (Java 17 / Spring Boot), контейнеризация через Docker, оркестрация - Kubernetes, асинхронное взаимодействие через Apache Kafka. Работал в кросс-функциональной продуктовой команде по Scrum.

**Сервис нормативно-справочной информации (reference-data)**  
Реализовал и развивал REST API централизованного хранилища справочников:  
- CRUD-операции, валидация атрибутов по JSON Schema, soft-delete и версионирование записей (сохранение историчности для уже подписанных документов).  
- Стек: Spring Boot, Spring Data JPA, Liquibase.

**Сервис глобальных настроек платформы**  
- Реализовал механизм разрешения эффективного значения параметра с приоритетом «клиент → филиал → глобальный уровень».  
- Разработал эндпоинты пакетной загрузки индивидуальных настроек клиентов (асинхронная обработка, валидация, отчёт об ошибках).  
- Покрыл ключевую бизнес-логику unit- и интеграционными тестами (JUnit, Mockito, Testcontainers).

**Сервис счетов на оплату**  
- Реализовал эндпоинты создания, выставления и отслеживания статусов счетов.  
- Настроил публикацию событий изменения статуса в Kafka.  
- Внедрил быстрый слой дедупликации входящих событий оплаты через Redis (в сочетании с идемпотентной записью в PostgreSQL).

**Сервис заявок РКО**  
- Дорабатывал формы заявок по требованиям бизнес-аналитиков.  
- Оптимизировал SQL-запросы (JOIN, составные индексы) для ускорения выборки по клиенту.

Участвовал в код-ревью внутри команды.

**Результаты**  
- Снизил p95 latency API справочников с 180 мс до 117 мс (≈35 %) за счёт индексов и кэширования часто запрашиваемых значений в Redis.  
- Сократил объём ручных операций по настройке клиентов — массовые изменения выполняются через API пакетной загрузки.  
- Устранил дублирование уведомлений о статусе оплаты благодаря дедупликации событий через Redis.  
- Ускорил поиск заявок РКО: среднее время SQL-запроса снизилось с 800–900 мс до 200–250 мс.  
- Повысил покрытие unit- и интеграционными тестами ключевой логики двух сервисов с 45 % до 80 %.

**Технологии**: Java 17, Spring Framework (Boot, Data, Security, Actuator, Web), PostgreSQL 12, Liquibase, Apache Kafka, Redis, Elasticsearch, Kotlin, Git, REST, OpenAPI/Swagger, gRPC.
